# BioCartoon

BioCartoon is a free and open-source tool for creating bio cartoons and biology figures. We compile existing open biology-focused illustration resources and introduce our own illustrations in a single database with a graphical interface for search and figure generation.

This repository holds the icon database and the `biocartoon` command-line interface. The desktop app, web app, and website are in [biocartoon-app](https://github.com/josephrich98/biocartoon-app).

## Usage

Web application: [app.biocartoon.com](https://app.biocartoon.com)

Install Desktop application: [www.biocartoon.com/download](https://www.biocartoon.com/download)

AI assistants (ChatGPT, Claude, Codex, ...): connect the MCP server `https://mcp.biocartoon.com/mcp`, see [AI assistants](#ai-assistants)

## AI assistants

BioCartoon has an MCP server and agent skills, so you can work with the library from a chat with
ChatGPT, Claude or a coding agent. Without leaving the conversation, you can:
- search the library, see previews of the candidates, and download the ones you want with their credit lines
- when nothing fits, have the assistant draw an illustration (Claude, as SVG) or generate one
  (ChatGPT), refine it with you, and submit it to the shared library
- adapt an existing icon ("like BA001505, but with the nucleus in blue"): the assistant reads the
  icon's SVG and edits it
- make a whole figure ("a schematic of antigen presentation to T cells"): the server picks an icon for
  each element and lays them out with labels, arrows and a title (`compose_figure`). Elements with no
  fitting icon become labelled boxes. You get a preview, SVG/PNG downloads, the credit lines, and a link
  that opens the figure in the BioCartoon editor as your own editable copy

Submissions are held for review like any other upload.

The hosted server is `https://mcp.biocartoon.com/mcp` (Streamable HTTP, no sign-in).
It runs on Cloudflare Workers Free with a separate public D1 catalog; it needs no Container
or paid-plan upgrade. See [Plugin development and deployment](#plugin-development-and-deployment).

The plugin bundles the four skills and this MCP connection. In hosts supporting MCP Apps,
the assistant shows icons, templates and composed figures in an interactive gallery. It has
a search bar with sort and filters (database, author, category, license, file type, tags,
artwork type). Each card offers **Edit**, which sends your change request to the assistant,
**Download** (SVG or PNG), **Open in BioCartoon**, and a credit and license dropdown with a
copy button. Clients without app UI still get the same records and links as text.

Editor links are share links (`app.biocartoon.com/#share=...`). The MCP server encrypts the
project, and the decryption key is only in the link's fragment. Links from all MCP users
share one allowance on the submissions Worker (`X-MCP-Token`).

**ChatGPT**: the portable plugin package bundles the skills and the MCP App connection;
an installed package needs no separate connector. To test just the server URL manually,
use developer mode (under Apps / Connectors > Advanced):
- Create a connector with the MCP server URL `https://mcp.biocartoon.com/mcp` and no authentication.
- In a chat, turn on BioCartoon from the tools (+) menu.
- ChatGPT passes images it generated, or that you attached, straight to `submit_artwork`.

**Claude** (claude.ai, desktop and mobile apps): install the BioCartoon plugin, which bundles the
skills and the hosted MCP connection. Without the plugin:
- Settings > Connectors > Add custom connector, with the URL `https://mcp.biocartoon.com/mcp`.
- Optional: add the skills too. Upload each skill's zip (built by `scripts/package_claude_plugin.py`
  into `dist/claude-skills/`, or zip each folder in [`catalog/skills/`](catalog/skills)) under
  Settings > Capabilities > Skills.

**Claude Code**: install the plugin, which includes the skills and hosted MCP connection.
The skills can also run the `biocartoon` command (`pip install biocartoon`), including
submitting files from your computer:

```
/plugin marketplace add josephrich98/biocartoon
/plugin install biocartoon@biocartoon
```

Without the plugin, add the hosted server directly, or run it on your own computer:

```bash
claude mcp add --transport http biocartoon https://mcp.biocartoon.com/mcp
# or
pip install biocartoon
claude mcp add biocartoon -- biocartoon mcp
```

Without the plugin, `biocartoon install-skills` installs the skills.

**Codex**: the plugin includes the skills and hosted MCP connection:

```bash
codex plugin marketplace add josephrich98/biocartoon
codex plugin add biocartoon@biocartoon
```

Without the plugin: `codex mcp add biocartoon --url https://mcp.biocartoon.com/mcp`, or
`codex mcp add biocartoon -- biocartoon mcp` to run the server locally.

**Any other agent or MCP client**:
- Remote clients: use the URL above.
- Local clients: run `biocartoon mcp` (stdio).
- Skills: `biocartoon install-skills --dest DIR` copies them into DIR, or
  `biocartoon install-skills --agent codex` installs them for Codex.

The skills:

| skill | what it does |
|---|---|
| [`biocartoon-find-icons`](catalog/skills/biocartoon-find-icons/SKILL.md) | search, judge and preview illustrations, download them, and give their credit lines |
| [`biocartoon-create-icon`](catalog/skills/biocartoon-create-icon/SKILL.md) | check the library, draw or generate a new illustration in its style (or adapt an existing icon), confirm the details with you, and submit it |
| [`biocartoon-upload`](catalog/skills/biocartoon-upload/SKILL.md) | upload image files or a folder with `biocartoon upload`: write each one's details, dry-run, upload once you confirm, and update earlier uploads |

The MCP tools:

| tool | what it does |
|---|---|
| `search_assets` | icons matching words, optionally only some collections or tags |
| `preview_assets`, `asset_image` | look at up to 12 icons side by side, or at one in more detail |
| `render_assets` | show up to 12 selected icons in an interactive gallery, with credits and PNG/SVG links; text fallback in other clients |
| `get_asset`, `asset_variants` | everything about an icon (license, credit line, PNG/SVG links), and its other colour schemes |
| `asset_svg` | an icon's SVG markup, to adapt it, and whether its license lets an adaptation be submitted |
| `browse_assets`, `list_sources`, `list_categories` | page through a collection or one of its categories |
| `sql_query`, `db_schema` | read-only SQL on the catalog |
| `list_templates`, `template_image` | shared whole-slide templates |
| `submit_artwork` | submit an illustration for review, given as SVG markup, a conversation file, an https URL, base64 or (local server only) a file path; `derived_from` names the icon it adapts |
| `submission_status` | whether submissions are pending, approved or rejected |

The server only submits after the user confirms (`rights_confirmed`). Artwork made with generative AI
can be submitted only under CC0.

An adaptation must keep the original icon's license terms, so the server checks `derived_from` before
submitting:
- public domain and CC0 originals can be adapted and submitted under either license
- CC BY, MIT and BSD originals only as CC-BY-4.0, made without generative AI
- CC BY-SA originals (OpenMoji, a few Bioicons) not at all

It adds the original's credit line to the description. Any icon can still be adapted for your own
figure, credited as its license requires.

To run the HTTP server yourself:
- `biocartoon mcp --http` serves it at `http://127.0.0.1:8080/mcp`. Use `--listen ADDR`, or set
  `PORT` to listen on `0.0.0.0:$PORT`.
- Or run it from the container: `docker build -t biocartoon-mcp catalog && docker run -p 8080:8080 biocartoon-mcp`.

### Plugin development and deployment

The repo's Codex/Claude compatibility manifests use `.mcp.json`. Portable packages use
`mcp.json` with the same endpoint. The skill sources remain in `catalog/skills/` so the CLI
can embed them. Build a portable private package containing both the skills and connection:

```bash
python3 scripts/package_plugin.py
# dist/biocartoon-VERSION.zip (the ChatGPT/Codex plugin, no account upload or publication)
python3 scripts/package_claude_plugin.py
# dist/biocartoon-claude-VERSION.zip (the Claude plugin) and dist/claude-skills/NAME.zip (one per skill)
```

Each channel updates differently. The hosted server's tools, instructions and gallery reach every
assistant as soon as `npm run deploy:mcp` runs. The skills and manifests reach Claude Code plugin
and `biocartoon install-skills` users with the next `v*` release, and ChatGPT and Claude app users
only when a new package is uploaded. `biocartoon-app/deploy.sh plugin` (part of `deploy.sh all`)
builds both packages and warns what needs a release or an upload, by comparing with the
`plugin-portal` (ChatGPT) and `claude-plugin-portal` (Claude) tags; `deploy.sh plugin --uploaded
[chatgpt|claude]` moves them after an upload.

The gallery uses the standard MCP Apps bridge and ships as an embedded, self-contained
HTML resource (`ui://biocartoon/icon-gallery-v2.html`). `search_assets` remains a data tool;
after judging results, the assistant calls `render_assets` with selected IDs. The gallery
can call the same search and variant tools without opening another widget. Its only external
image origin is https://assets.biocartoon.com, and it does not contact the API directly.

```bash
cd catalog/ui
npm ci
npm run typecheck
npm run build
npx playwright install chromium
npm test
```

Commit `catalog/ui/dist/gallery.html` with UI source changes. This lets plain Cargo and PyPI
builds embed the gallery without requiring Node. CI rebuilds and checks that it matches.
The Docker build also rebuilds the UI before compiling Rust. Run `cargo test --release`
from `catalog/` to check the server and catalog.

The hosted server uses TypeScript MCP handlers and D1's indexed full-text search.
It serves the same gallery and tool contracts as the Rust server. There are no Containers,
Durable Objects, paid image transforms or AI APIs in this deployment. Its submission service
binding reuses the existing `biocartoon-submit` Worker, including validation, rate limits,
storage and human moderation. No new image bucket is created.

Keep the Cloudflare account on **Workers Free** for a hard $0 backend limit: quotas stop
requests/queries rather than adding overage charges. The account's existing image storage
and submission service retain their own limits and costs. The hosted endpoint accepts
PNG/SVG artwork up to 2 MB; use the local CLI for conversion and resizing.

The tool metadata is generated from the local server so tool names, skills and gallery
resource IDs remain consistent. Rebuild it when changing the Rust tool definitions:

```bash
cd catalog
cargo build --release --locked --bin biocartoon
cd ..
python3 scripts/build_mcp_metadata.py
```

For initial deployment on a verified free-plan account:

```bash
python3 data/export_mcp_catalog.py       # published public snapshots -> dist/mcp-catalog.sql
cd worker
# For a new account only: create biocartoon-catalog with Wrangler and update its database_id
# in wrangler.mcp.jsonc. Keep it separate from biocartoon-submissions.
npm ci
npm run import:mcp:local
npm run dev:mcp                         # local MCP + D1 on http://localhost:8789/mcp
# First remote import only (it replaces the public catalog):
npm run import:mcp
npm run deploy:mcp
```

Later publishes automatically sync changed catalog rows to D1 (use `publish_catalog.py --no-mcp`
to skip). This avoids rewriting the entire catalog against the free daily write allowance.
If a sync hits a quota, the publisher reports the failure without undoing its R2 publication
or backup. Retry after the quota resets with
`python3 data/sync_mcp_catalog.py` (`--dry-run` compares without writing).

Check the live endpoint with `node scripts/check_mcp.mjs`. It checks tool discovery, gallery
resources, search, downloads, templates, submission status and refusal of unconfirmed artwork;
it does not create a submission. Then update the plugin through its existing release process.
The package builder does not change an installed account plugin.

Every push and pull request also builds and validates the public submission draft.
Download `biocartoon-submission-COMMIT` from the `submission` job's GitHub Actions
artifacts (retained for 14 days). It includes the public plugin ZIP, review materials,
commit and file hashes, and a report of missing fields and changes since the recorded
review contract. Build it locally with `python3 scripts/prepare_submission.py`.
Review cases, policies and recordings remain curated; builds do not mark them passed
or submit the plugin to OpenAI. See [submission preparation](submission/README.md).

`npm run deploy:mcp` runs the read-only live check after a successful deploy. A failed
check reports failure without undoing the deployment. GitHub's `MCP live checks`
workflow also runs on successful deployment statuses for the `biocartoon-mcp`
environment, or manually from Actions, and saves result artifacts. Direct Cloudflare
dashboard deployments need that GitHub status event or a manual check.

## Command-Line Interface and MCP server

The `biocartoon` command searches the published catalog from a shell:

```bash
pip install biocartoon
```

If your shell then says `biocartoon: command not found`, pip put the program in a folder that is
not on your PATH (pip names it in a warning near the end of its output): add that folder to PATH,
or install with `pipx install biocartoon` or `uv tool install biocartoon`, which handle PATH for you.

The package is the compiled program alone, with no Python dependencies. To build it from source
instead, run `cd catalog && cargo build --release` (giving `target/release/biocartoon`). This
build searches icons; its MCP server also lists the shared slide templates. The BioCartoon desktop
editor ships a fuller `biocartoon` that adds templates to `search` and the `app` command.
On Windows, the build also needs the Visual Studio Build Tools with the C++ workload
(`winget install Microsoft.VisualStudio.2022.BuildTools --override "--passive --wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"`),
and must run from PowerShell or cmd: Git Bash's own `link` command shadows the MSVC linker.

- `biocartoon search "TERM"`: icons and templates matching TERM, best first. With no TERM it pages
  through everything.
    - `--icons` / `--templates`: only that kind
    - `--tags T,...`: icons and templates with one of these tags (a whole tag, any case)
    - `--source S`: icons from a collection (a code or name from `biocartoon --sources`)
    - `--author A`: icons by an author (part of the name, any case)
    - `--category C`: icons in a category (a slug from `biocartoon --categories`)
    - `--subcategory S`: icons in a subcategory (a slug from `biocartoon --categories`)
    - `--source-category [S:]C`: icons in a collection's own category (from `biocartoon --source-categories`)
    - `--license L`: icons under a license (`CC-BY-4.0`, `CC0-1.0`, ...)
    - `--file-type svg|png`: icons published as SVG, or as a PNG only

    Repeat a filter for several values: an icon matching any of them passes. An icon has to pass
    every filter given.
    - `--sql`: run TERM as read-only SQL on the catalog. 
- `biocartoon get ID`: everything about one icon: license, credit, PNG/SVG URLs, colour variants
- `biocartoon fetch ID`: download the SVG, or the PNG when the source publishes no SVG (`--png` or `--svg` for that type only, `--out FILE|DIR`, `--max-side N` for a smaller PNG)
- `biocartoon sync`: download the newest published catalog
- `biocartoon bulk-download`: the whole catalog into one folder with a README (contents, licenses, and the equivalent curl/sqlite3 commands, which it also prints as it goes); running it again fetches only what is missing
    - `--files all|metadata|artwork|icons|templates`: what to get (comma-separate several; `artwork` is icons and templates; default `all`)
    - `--metadata-ext sqlite|csv|tsv|xlsx|json`: the icon and template catalogs' format (default `sqlite`)
    - `--artwork-ext png|svg`: sets both of the next two (templates have no SVG, so they come as PNG)
    - `--icons-ext svg|png`: default `svg`, with a PNG where the source publishes no SVG
    - `--templates-ext png|biocartoon`: the thumbnail (default), or a `.biocartoon` file the editor opens
    - `--output-dir DIR` (default `./biocartoon-catalog`), `--jobs N` (parallel downloads, default 8), `--limit N` (the first N of each, to try it out)
- `biocartoon upload FILE...`: submit images files/folders to the database (approval required to merge in)
    - `--update ID`: submit one file as a new version of an upload (`UG000123`, `BC000123` or `user/<id>`). With no FILE, the current image is kept and only the details you give change. Needs an upload key (`--key KEY` or `BIOCARTOON_UPLOAD_KEY`) provided by a developer.
- `biocartoon app CMD [JSON]`: drive the running desktop editor (editor's build only) --- requires the desktop app
- `biocartoon mcp`: serve the same tools, and artwork submission, over MCP for AI assistants (e.g., `claude mcp add biocartoon -- biocartoon mcp`); see [AI assistants](#ai-assistants)
    - `--http`: over Streamable HTTP at `http://ADDR/mcp` instead of stdin/stdout, for remote clients (`--listen ADDR`, default `127.0.0.1:8080`, or `0.0.0.0:$PORT` when `PORT` is set; `--threads N`)
- `biocartoon install-skills`: install the agent skills for Claude Code (`~/.claude/skills`), `--agent codex`, or `--dest DIR` (`--list`, `--uninstall`, `--overwrite`)
- `biocartoon --version`: the program's version, and when the local catalog was published and downloaded
- `biocartoon --sources`: list icon sources for `biocartoon search --source S`
- `biocartoon --categories`: list icon categories for `biocartoon search --category C`
- `biocartoon --source-categories`: list the collections' own categories for `biocartoon search --source-category S:C`
  
## Examples

Find an icon, check its license, and download it:

```bash
$ biocartoon search mitochondria --icons --limit 2
BA001199                           bioart       Mitochondria  (Cells and Organelles; 2084x2084)  matched: title,description
BA000413                           bioart       Damaged Mitochondria  (Cells and Organelles; 1705x1174)  matched: title,tags,description

$ biocartoon get BA001505              # credit, license, PNG/SVG URLs, colour variants
$ biocartoon fetch BA001505 --out ~/Desktop               # the SVG
$ biocartoon fetch BA001505 --max-side 512 --out neuron.png   # a smaller PNG
```

Contribute your own illustrations (held for review before they are published):

```bash
biocartoon upload figures/ --license CC-BY-4.0 --credit "Your Name" --dry-run   # check first
biocartoon upload figures/ --license CC-BY-4.0 --credit "Your Name" --category cells --tags "neuron, axon"
biocartoon upload neuron-fixed.svg --update UG000123 --key "$BIOCARTOON_UPLOAD_KEY"   # a new version of an upload
biocartoon upload --update UG000123 --tags neuron,axon --key "$BIOCARTOON_UPLOAD_KEY"   # new details, same image
```

Narrow a search by collection, category, author, license or file type:

```bash
biocartoon --sources                                       # codes: BA, BI, SV, SD, HI, RE, OM, ...
biocartoon --categories                                    # slugs: cells, cells.cell_types, ...
biocartoon search "pyramidal neuron" --source BA           # NIH BioArt only
biocartoon search neuron --source BA --source SD           # BioArt or SciDraw
biocartoon search mitochondria --category cells.organelles_and_cell_components
biocartoon search --category viruses --sort az --limit 40 --offset 40   # page 2 of all viruses
biocartoon search neuron --subcategory cell_types --file-type svg            # SVG cell types
biocartoon search --license CC0-1.0 --license PD --category cells            # free of attribution
biocartoon search --author kissinger --source BA --sort popular              # one illustrator
biocartoon search --source-category "BA:Cellular Processes" --source-category "BA:Proteins"
biocartoon --categories --source SD                        # what SciDraw covers
```

Icons, templates or both (templates need the editor's build of `biocartoon`):

```bash
biocartoon search "cell"                                   # icons, then templates
biocartoon search "cell" --icons
biocartoon search "cell" --templates
```

Query the catalog with SQL (read-only):

```bash
biocartoon search --sql                                    # the schema
biocartoon search "select license, count(*) as n from assets group by license order by n desc"
# warning: running the search term as SQL; pass --no-sql to search for the words instead
biocartoon search --sql "select id, title from assets where svg_key is not null and title like '%ribosome%'"
biocartoon search "with dendrites" --no-sql                # words, even though it starts with WITH
```

From a script: every command takes `--json`, and search results come back as
`{"icons": [...], "templates": [...]}`:

```bash
# download the SVG of the best match that has one (Servier and uploads are PNG only)
mkdir -p icons
for t in neuron astrocyte microglia; do
  id=$(biocartoon search "$t" --icons --limit 10 --json | jq -r '[.icons[] | select(.svg_url)][0].id')
  biocartoon fetch "$id" --svg --out icons/
done
biocartoon get BA001505 --json | jq -r .credit     # the attribution line to print
```

Drive the running desktop editor (editor's build only):

```bash
biocartoon app state                                       # page size and every item on the slide
biocartoon app insert_asset '{"asset":"BA001505","x":200,"y":120,"width":300}'
biocartoon app move_items '{"ids":[3],"dx":48}'
biocartoon app render '{"path":"slide.png"}'
```

Download the whole catalog (well over 1 GB), or parts of it:

```bash
biocartoon bulk-download                                   # everything, into ./biocartoon-catalog
biocartoon bulk-download --files metadata --metadata-ext xlsx       # the catalogs as spreadsheets
biocartoon bulk-download --files icons --icons-ext png --output-dir icons/
biocartoon bulk-download --files templates --templates-ext biocartoon   # templates to open in the editor
```

Keep the local catalog current, and connect an assistant:

```bash
biocartoon sync
claude mcp add biocartoon -- biocartoon mcp
```

## Database Structure

The catalog is published as two gzipped SQLite files, built from the master database
(`data/assets.sqlite`) by `data/publish_catalog.py`. File keys (`svg_key`, `png_key`, `json_key`,
`thumb_key`) are paths in the public bucket, so a file lives at `https://assets.biocartoon.com/<key>`.

### `assets.sqlite.gz`

One row per icon in the `assets` table. Only rows that are uploaded to the bucket and have a PNG are published.

| column | type | description |
|---|---|---|
| `id` | TEXT, primary key | two letters for the source (`BA` bioart, `BI` bioicons, `HI` healthicons, `NE` noto, `OM` openmoji, `RE` reactome, `SD` scidraw, `SV` servier, `UG` user upload, `BC` an upload in the official BioCartoon library), then a number unique across the catalog (e.g. `BA001505`); never reused |
| `source` | TEXT | short source name: `bioart`, `bioicons`, `healthicons`, `noto`, `openmoji`, `reactome`, `scidraw`, `servier`, `user` |
| `source_name` | TEXT | display name of the source (e.g. `Servier Medical Art`) |
| `source_id` | TEXT | the asset's id in the upstream collection; unique together with `source` |
| `title` | TEXT | asset title |
| `variant` | TEXT | BioArt colour scheme or Health Icons style, when the source has variants |
| `description` | TEXT | upstream description, if any |
| `category` | TEXT | the source's category path (e.g. `Anatomy and The Human Body / Cardiovascular system / Arteries`) |
| `tags` | TEXT | JSON array of keywords (the source's, or the uploader's) |
| `license` | TEXT | normalized license: `PD`, `CC0-1.0`, `CC-BY-3.0`, `CC-BY-4.0`, `CC-BY-SA-3.0`, `CC-BY-SA-4.0`, `MIT`, `BSD`, `Apache-2.0` |
| `license_raw` | TEXT | the license as the source states it |
| `license_url` | TEXT | link to the license text |
| `attribution_required` | INTEGER | 1 if the license requires credit |
| `share_alike` | INTEGER | 1 if derivatives must use the same license |
| `author` | TEXT | artist or contributor |
| `source_url` | TEXT | the asset's upstream page |
| `doi` | TEXT | DOI, where the source gives one |
| `credit` | TEXT | ready-to-display attribution line |
| `svg_key` | TEXT | bucket key of the SVG; NULL for raster-only assets |
| `png_key` | TEXT | bucket key of the PNG |
| `png_is_raster` | INTEGER | 1 if the PNG was rendered by us from the SVG |
| `png_width`, `png_height` | INTEGER | PNG size in pixels |
| `thumb_key` | TEXT | bucket key of a small PNG preview (at most 256 px a side, `thumbs/<png_key>`) for search results; NULL when there is none yet |
| `svg_bytes`, `png_bytes` | INTEGER | file sizes |
| `svg_sha256`, `png_sha256` | TEXT | file checksums |
| `svg_local`, `png_local` | TEXT | build-time paths under `data/`; empty in the published catalog |
| `extra` | TEXT | JSON of source-specific fields (e.g. BioArt accession and collection) |
| `uploaded_at` | TEXT | ISO 8601 time the files were uploaded to the bucket |
| `stars` | INTEGER | star count from users of the app |

Indexes cover `source`, `license`, `category` and the unique pair (`source`, `source_id`).
`assets_fts` is an FTS5 full-text index (Porter stemming) over `title`, `description`, `tags`,
`category` and `variant`, joined to `assets` by `rowid`:

```sql
SELECT a.id, a.title, a.license, a.png_key
FROM assets_fts JOIN assets a ON a.rowid = assets_fts.rowid
WHERE assets_fts MATCH 'mitochondria' ORDER BY rank LIMIT 10;
```

### `templates.sqlite.gz`

One row per slide template in the `templates` table.

| column | type | description |
|---|---|---|
| `id` | TEXT, primary key | `<slug>-<hash>` (e.g. `eukaryotic-cell-5a1e09d5a6`) |
| `title` | TEXT | template title |
| `description` | TEXT | short description |
| `category` | TEXT | BioCartoon category (e.g. `Cell biology`) |
| `tags` | TEXT | JSON array of keywords the author gave it (`[]` for none) |
| `author` | TEXT | template author |
| `license` | TEXT | normalized license, as in `assets` |
| `created_at` | TEXT | ISO 8601 creation time |
| `json_key` | TEXT | bucket key of the template document (`templates/<id>/template.json`) |
| `thumb_key` | TEXT | bucket key of the thumbnail (`templates/<id>/thumb.png`) |
| `json_local`, `thumb_local` | TEXT | build-time paths; empty in the published catalog |

A `meta` key–value table (`k`, `v`) is reserved for catalog metadata.
